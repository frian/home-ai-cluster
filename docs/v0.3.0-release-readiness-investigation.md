# v0.3.0 Release-Readiness Investigation

Status: Current investigation

Date: 2026-08-21

## Scope

This documentation-only investigation compares current `main` with the
published `v0.2.0` baseline to decide whether Home AI Cluster can move to a
small `0.3.0` release-preparation PR. It covers package, documentation, CLI,
tests, built artifacts, and the existing release workflow.

It does not prepare a release, change the version, create or move a tag,
publish a package, or rerun operator-owned live integrations. The separately
installed SearXNG plugin repository was not changed.

## Baseline

- Historical stable baseline: annotated tag `v0.2.0`, resolving to
  `1c3b9c188b5f512e607c480a5a0f4e0e2f52a5e1`.
- Investigated current `main`: `147e1a6`.
- Package version: `0.3.0.dev0`; declared Python range: `>=3.13,<3.15`.
- The tree was clean before the investigation and the remote `main` view was
  synchronized before creating this documentation branch.

The existing release workflow is manual only. It requires dispatch from
`main`, an exact `vX.Y.Z` input, and an annotated tag checked out at its tagged
commit. It then requires an exact package-version/tag match, builds wheel and
sdist with Python 3.13, checks exact filenames, runs Twine and metadata checks,
and smoke-tests an installed wheel. It transfers artifacts to a separate
`pypi` environment job whose only permission is OIDC `id-token: write` and
uses Trusted Publishing without a token fallback.

## Material changes since v0.2.0

The meaningful release-facing additions are:

- **Capabilities and routing:** `classify` and bounded textual `code` join
  `chat` and `summarize`; routing, adapters, and static declarations enforce
  their explicit eligibility while keeping ordinary Chat-compatible paths
  bounded.
- **Operator surfaces:** the unified `hac`/`home-ai-cluster` root now has 12
  documented subcommands, including ordinary request clients, inspection
  commands, runtime composition, and static-cluster operation.
- **Developer-tool access:** the bounded `hac aider` caller edge coordinates
  the accepted Aider version with at most two native `code` requests; it does
  not give HAC edit, shell, Git, or test authority.
- **Source-grounded Chat:** RFC-0077 adds bounded supplied evidence and
  `POST /v1/chat/sources`, preserving ordinary `capability=chat` routing and
  separating supplied-source provenance from answer correctness.
- **External-information boundary:** RFC-0078 adds the explicit,
  separately-installed entry-point caller edge. RFC-0079 defines the first
  fixed-loopback SearXNG plugin contract in a separate repository; no provider
  is bundled with HAC and ordinary HAC does not discover or load plugins.
- **Packaging and release:** project URLs and AGPL metadata were added; the
  stable Trusted Publishing workflow replaced the historical one.
- **Records and proofs:** investigations, runbooks, and retained proofs were
  added. Their current index labels them as records, and the inspected
  source-grounded and SearXNG proofs make no broader reliability, source
  correctness, or model-answer-correctness claim.

The change set also contains internal model, transport, validation, and routing
refinement needed to implement those accepted RFCs. It is not presented as a
new general plugin system, provider capability, or automatic acquisition path.

## Findings

1. **Should fix before release — Ruff formatting check fails.**
   `ruff format --check .` reports five existing files: one retained Aider
   runbook and four test files. This is a mechanical, narrow formatting-only
   follow-up; it is not fixed here. A dedicated formatting PR should run the
   configured Ruff formatter only on those reported files and verify the full
   suite afterward.

2. **Informational — release tooling is intentionally workflow-owned.**
   The checkout development environment does not itself install `build` or
   `twine`; the release workflow installs both before using them. Temporary
   standard-tool validation passed, so this is not a packaging gap.

No package metadata, artifact, import, installed entry-point, CLI-help,
release-facing link, or documentation/accepted-boundary mismatch was found.

## Live-proof coverage

No Ollama, llama-server, Aider, SearXNG, external provider, or installed
SearXNG plugin was installed, started, configured, or invoked for this
investigation. Those are operator-owned integrations, not package-installation
prerequisites.

The retained RFC-0077 source-grounded Chat proof covers real local supplied-
source execution and records its factual-grounding and prompt-injection limits.
The retained RFC-0078 proof covers installed entry-point discovery and bounded
caller reconstruction. The RFC-0079 retained result covers one complete real
installed-plugin, fixed-loopback SearXNG, RFC-0078/RFC-0077, ordinary Chat,
routing, and runtime-adapter path. These are bounded observations, not claims
of provider reliability, search-result correctness, or model-answer
correctness.

## Release workflow assessment

The current workflow is suitable for a future `0.3.0` release-preparation
commit and annotated `v0.3.0` tag. Its artifact checks use the normalized
`home_ai_cluster` filename prefix and its clean-install smoke check remains
valid as the root CLI has grown: it verifies the distributable package and
`hac --help`, while this investigation additionally checked the newer
non-network command-help surfaces from a clean install.

No workflow change is required by this investigation. The workflow must not be
dispatched while `pyproject.toml` remains at `0.3.0.dev0`, because its exact
stable tag/version validation correctly rejects that state.

## Final outcome

### Outcome B — small fixes required

One or more small release-preparation fixes are required before the v0.3.0
preparation PR.

Required follow-up:

1. Create a dedicated formatting-only PR that resolves the five files reported
   by `ruff format --check .`, then rerun Ruff and the full suite.

After that correction, the investigation evidence supports a small `0.3.0`
release-preparation PR. This investigation itself leaves the version at
`0.3.0.dev0` and authorizes no release action.
